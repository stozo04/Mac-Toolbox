## A. Loose ends from phase 1

**A1. A yt-dlp helper process can survive when its parent is killed.**
- Why: `Shell.run` signals one process. yt-dlp (a PyInstaller binary) and a merge ffmpeg run as children; killing the parent leaves them writing.
- Do: reproduce with a stand-in script that starts a child and prints both pids. Fix in `Support/Shell.swift` so every tool gets it: start the program in its own process group and signal the group on cancel, timeout and quit (SIGTERM, then SIGKILL after the grace period). `Process` does not expose `setpgid`; check whether `posix_spawn` with `POSIX_SPAWN_SETPGROUP` is needed and what that costs. `.untilFinished` runs are still never signalled.
- Done when: a test shows parent and child both gone after cancel, after timeout and after `stopChildrenBeforeQuit`; the cancel test still passes 0 of 960.

**A2. Quitting during vault creation leaves the creation running once the wait runs out.**
- Why: by Steven's rule the creation is never killed. After the app exits, `diskutil` loses its output pipes. Nobody has checked that it always finishes cleanly.
- Do: on a throwaway vault folder only, start a real create, exit the parent process partway, and see whether the image is complete and attachable afterwards. Create writes to a temporary name and is moved into place by the app, so an orphaned create leaves only a temporary image: confirm that, and that the next launch cleans it up or reports it. Repeat enough times to trust the answer.
- Done when: the behaviour is written in `features/Vault/README.md` with the evidence, and anything wrong is fixed with a test.

**A3. Screen Recorder's teardown fix has no test.**
- Why: `ScreenRecorder.stop()` was changed (PR #34) to release the click highlighter and microphone session on the capture queue, by reasoning only.
- Do: find a seam that needs no real recording (inject the stream and helpers, or factor the ordering into a small type that records what was torn down on which queue). Never start a real screen recording in a test.
- Done when: a test fails on the pre-#34 ordering and passes now; or a written reason why no seam is possible.

## B. Swift 6 language mode (approve first)

- Why: the compiler would have caught several of this review's concurrency bugs. Measured on 2026-11-17: 38 unique warnings in 15 files on the app target with `-strict-concurrency=complete` (ModelsView 7, VideoCompressor 7, RecordScreenModel 4, VaultSearchEngine 3, MainWindowReopener 3, the rest 1 or 2). The test target was not measured.
- Do: re-measure both targets. `Package.swift` to `swift-tools-version: 6.0` with Swift 6 mode on `Toolbox` and `ToolboxTests`. CI's compiler is older than this Mac's (PR #34 failed on an API CI lacked): check `xcodebuild -version` in a CI log first and use nothing newer. `VaultSearch` and `CWebP` stay as they are unless the build forces a change.
- Rules: fix causes, do not paper over. Every new `@unchecked Sendable`, `nonisolated(unsafe)` or `@preconcurrency` is listed in the PR with the reason it is safe. No behaviour change is intended; say so if one is needed.
- Done when: both targets build with zero concurrency warnings in Swift 6 mode locally and in CI, full suite passes twice.
- Risk: large diff across many files. Do it before C to H so those are written under the stricter compiler.

## D. Scan Document memory

- Why: the model is a `.shared` singleton holding a full-size `CGImage` per page for the whole session. By arithmetic, 50 iPhone photos is about 2.4 GB and a 200-page PDF at 200 dpi about 3 GB, never released.
- Do: measure real memory first (import 50 photos; read `phys_footprint`). Keep a working copy at about 1,600 px, or a temp file, per page; render full size only inside `makePDF`; release everything when the pages are cleared.
- Done when: measured memory for 50 photos drops by the expected order, saved PDFs are pixel-comparable to before (test on a fixture), OCR quality is unchanged on the test fixtures.
- Risk: the invisible text layer and straightening use the image; make sure they read the full-size source when saving.

## E. Vault performance leftovers (approve first)

Nothing here may weaken PR #35's import safety (mounted-volume check, exclusive copy through one descriptor, flush before delete, truthful not-moved list) or PR #40's lock design.

- **E1. Each imported file is read three times** (the copy, then a hash of copy and original, plus a decode to check it opens). Hash the source while copying so it is read once; the copy must still be read back from the vault for the comparison, or the check proves nothing.
- **E2. The viewer decodes full-size images.** Decode to the display size with ImageIO thumbnails; keep full size for zoom only if the viewer zooms.
- **E3. `displayedItems` and `searchSections` are recomputed on every access**, several times per redraw. Measure at 5,000 items with a query before deciding it matters: without a query it measured 0.12 ms at 1,500.
- **E4. Cached search vectors are thrown away after each stored file**, so a query during indexing reloads every vector from SQLite. Keep them and append.
- Done when: import time and viewer memory are measured before and after on a throwaway vault of 1,500 items, and every vault test passes.

## F. Smaller speed items (one small PR each)

- **F1. Remove Background** re-runs the Vision mask on every colour-picker change. Cache the mask per file.
- **F2. Blur Faces** decodes full resolution just to find faces. Detect on a thumbnail about 2,048 px on its longer side and scale the boxes. Check small faces in a large group photo are still found.
- **F3. Trim Audio** redraws all 400 waveform bars 30 times a second because the playhead shares the canvas's view body. Give the playhead its own view.
- **F4. Storage Explorer's scan** starts one task per entry, each a synchronous walk, which starves the shared task pool; each result re-sorts and re-lays-out a non-lazy stack. Limited-width queue, batched results, `LazyVStack`.
- **F5. Batch tools walk dropped folders on the main thread**, and AI Models looks up app icons in the view body. Move both off the hot path.
- Done when: each has a measurement or an Instruments observation before and after, in its PR.

## J. Remove comments that are not useful (approve first)

**Steven's decision: comments go, unless the comment is useful.**

- Why: about 1,080 `///` lines and several hundred `//` lines predate the comment rule. Many restate the name beneath them or narrate the code.
- What counts as useful, and stays: a specific, non-obvious **why** the code cannot say itself. A platform quirk. A safety reason. A workaround and its cause. A unit or a format that a type cannot carry. A warning about what breaks if the line changes.
- What goes: anything that restates the declaration ("The saved file"), narrates what the next lines do, or describes history. `// MARK:` lines are navigation, not commentary: keep them. Tool directives and the SHA-pin version tags in workflows are not comments.
- When deleting a comment leaves unclear code, the fix is a better name or a smaller function, not keeping the comment. Do that in the same PR only when it is a rename; anything larger is noted for later.
- Do not touch `Sources/CWebP` (vendored) or `Sources/VaultSearch` (kept close to DigUp's code).
- How, so it can be reviewed: one PR per area, none over about 600 changed lines: `Support/`, `Views/` and `Models/`, `AIModels/`, `Vault/`, `Tools/Video`, `Tools/Audio`, `Tools/Images` (two PRs), `Tools/Docs`, `Tools/Mac`, `Tests/`. Comment-only diffs: `git diff -w` must show no code change except the listed renames. Each PR's description gives the count removed and quotes the comments kept, so Steven can disagree with the judgment quickly.
- First step, before any PR: a sample. Take `Support/` only, apply the rule, and show Steven the kept and removed lists. His reaction sets the bar for the rest.
- Afterwards: write the rule into AGENTS.md (it is only in the global file today), and fix `.swiftlint.yml`'s header, which still describes "documented lines" as the house style.
- Done when: every area is done and the remaining comments are all whys.
